> **Split (2026-09-30):** this work is now two branches. `la-personalize` (this branch) is
> Personalize Responses only, for signed-in users. `la-anon-polish`
> ([ai-chatbot#230](https://github.com/Sefaria/ai-chatbot/pull/230)) is anonymous access only.
> Without anonymous mode the widget can't see a logout, so the stored memory is no longer
> cleared on logout: it stays with the browser. Sections below describe the original
> combined branch.

## Goals

1. **Every visitor gets a working Library Assistant.** Logged-out visitors get
   `CHATBOT_ANON_FREE_RESPONSES` (default 2) answers, then an in-canvas message with a
   login link. Signed-in users are unchanged: unlimited until they disable LA in settings.
2. **Personalize Responses.** A tab on the bottom edge of the chat canvas starts a scripted
   onboarding (4 questions). The answers become a permanent per-user memory that is added to
   the agent's system prompt on every turn and can be updated or cleared from the menu.

## Decisions

- **Anonymous identity is client-generated** (`anonId`, a UUID in `localStorage`), not a
  Sefaria-minted token. Sefaria's chatbot token is also a login credential
  (`SessionIDAuthMiddleware` reads it from `X-Session-ID`), so logged-out users must never get
  one. A client id also keeps the host page free of per-visitor data.
- **The quota is enforced server-side.** Persisted as `user_id = "anon:" + sha256(anonId)`;
  the stream endpoint counts successful responses across all of that id's sessions and
  returns `403 {"error": "login_required"}` once they are used up. The final SSE `message`
  (and `/v2/chat/recover`) carry `anonResponsesRemaining` so the widget can show the login
  prompt right after the last free answer. `CHATBOT_ANON_FREE_RESPONSES=0` turns anonymous
  chat off without a deploy of the host.
- **Known gap: no per-IP cap.** Clearing storage gets a new `anonId`, and a script can mint
  ids freely. The right place for a per-client limit is the edge (Envoy/Cloudflare), where
  the real client IP is known; doing it here risks keying on the load balancer's IP.
- **Memory is one editable text, a "user system prompt"** kept in the browser
  (`localStorage`, key `lc_chatbot:memory`) and sent with every message as `memory` (≤ 1000
  chars) on `POST /v2/chat/stream`. The server puts it verbatim inside `<learner_memory>`
  in that turn's prompt; nothing is stored server-side, and anonymous requests' memory is
  ignored. The questions run only the first time: each picked answer becomes a statement
  ("The user knows some Hebrew."), a typed answer stays as typed, and the last answer is
  appended verbatim. After that, "Update personal memory" opens a text editor (Save / Clear
  memory), not the questions. Chosen over a `UserMemory` table (built first, in this
  branch's history) because the Coolify PR preview doesn't run migrations. Trade-off: memory
  is per browser, not per account, and it is cleared when the widget sees a logout.
- **Prompt placement:** core prompt → memory → conversation summary → page context → message.
  The section tells the model to personalize to it but never let it override its other
  instructions, because the user writes it.
- **Onboarding is scripted in the widget**, not generated by the model: fixed copy,
  translatable, no model cost, and answers map to stable keys.
- Anonymous visitors don't see the Personalize tab (there is no account to save to).
